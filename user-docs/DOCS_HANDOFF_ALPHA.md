## What alpha 0.1.0 actually ships

### iOS app
- HealthKit sync covering activity, heart, body, sleep, workouts,
  nutrition, mindfulness, symptoms, medications, reproductive, and
  clinical records. Per-identifier sync strategy + demo-mode guard +
  client-side idempotency. Source of truth:
  `user-docs/HEALTHKIT_SYNC.md`.
- Camera-roll photo upload with EXIF capture date, GPS extraction,
  batch-import deferral, on-device caption.
- Structured screenshot extraction (vaccine cards, lab results,
  prescription labels) via Claude vision. Brand-name labels are
  paired with medical-concept descriptions so retrieval matches
  generic queries like "covid vaccinations" against brand-only
  labels (Comirnaty / Trulicity / etc.).
- Voice notes (with on-device transcript).

### Web app
- Ask, Home Insight, Timeline, Discover, Dossier, Episode, Review,
  Settings (provider connectors + LLM provider config).
- Processing animation on every blocking LLM surface.

### Backend
- FHIR sync from connected providers, with automatic `clinical_note`
  and `ccda_xml` extraction at sync time.
- Source Authority Doctrine: six-tier classifier driving retrieval
  order. Source of truth: `user-docs/SOURCE_AUTHORITY_DOCTRINE.md`.
- Retrieval tier-diversity round-robin across tiers.
- Category-aware retrieval aliases (vaccinations, allergies,
  appointments, instructions).
- Stateless upload-batch correlation: `X-Client-Batch-Id` /
  `X-Client-Item-Id` headers echoed in error JSON. Source of truth:
  `user-docs/UPLOAD_CONTRACT.md`.
- Single-host contract: `/api/*` served on the user's chosen
  hostname. No `api.` subdomain. Source: `user-docs/IOS_PARITY.md`.

### Reliability hardening for alpha
- Catch-all JSON error contract — no plain-text 500s.
- EXIF NUL-byte fix for iPhone screenshot JSONB writes.
- SourceDetail surfaces extraction state (status / fact count /
  error / relevance score) without log-spelunking.
- 80 pure-function pytest tests CI-protect the alpha-critical paths.

## Known backend / iOS gaps (deferred to beta)

Backend tracks these in the task list; Docs should mention them as
"known limitations" rather than overstate them.

- **Vision extractor doesn't pull `date_start` from PDF facts.**
  Alpine PDFs have 83 facts but NULL `date_start` — the LLM is
  extracting the dates but the pipeline isn't reading them off the
  PDF anchor.
- **clinical_note extractor stamps the ingest date as `date_start`
  for undated facts.** Should mark them `historical_undated` with
  NULL `date_start` (the date_origin taxonomy is pinned in tests
  but the extractor isn't using it yet).
- **FHIR Immunization → `fact_type='procedure'`**, not
  `'vaccination'`. The category alias for "vaccination" therefore
  only fires on iOS-extracted facts. Live FHIR-sourced flu shots
  still hit via substring match ("Influenza", "COVID-19") but the
  category-aware path misses them. Easy fix post-alpha: extend the
  FHIR mapping table.

## Install assumptions (Docs's reverse-proxy story)

Source of truth: `user-docs/INSTALL.md` + `user-docs/REVERSE_PROXY.md`
+ `user-docs/NETWORK_ACCESS.md`. The non-obvious points Docs should
foreground:

1. **OwnChart's `web` container speaks HTTP only**, on a single port.
   No native SSL. Operator MUST front it with a reverse proxy that
   terminates TLS (Nginx Proxy Manager, Caddy, Traefik, plain nginx).
2. **Reverse proxy MUST allow request bodies up to ~200 MB.** iPhone
   HEIC photos, multi-page PDFs, and CCDA archives routinely exceed
   the default 1 MB nginx ceiling. `client_max_body_size 200m;` (or
   equivalent) is non-negotiable for photo/PDF uploads. The app
   itself has no body-size cap.
3. **Network exposure: open a firewall port OR use VPN / Tailscale /
   Cloudflare Tunnel.** OwnChart has no IP-allowlist or rate
   limiter; isolation is the proxy's job.
4. **FHIR callback URL must be externally reachable.** Epic, athena,
   ModMed, etc. validate the OAuth `redirect_uri` byte-for-byte
   against what you registered with them. `OWNCHART_PUBLIC_BASE_URL`
   (in `infra/.env`) MUST match the hostname the vendor expects.
   "Localhost only" works for QA but not for live patient-mediated
   FHIR.
5. **Containers run as UID 1000.** Host `data/` directory must be
   owned by UID 1000 (the deploy script handles this; manual
   bootstrap requires `chown -R 1000:1000 data/`).

## Required environment variables

Source of truth: `infra/docker-compose.yml` + `api/ownchart/core/config.py`.

Auto-generated by `infra/deploy.sh` on first run; preserve across
deploys:

| Variable | Mandatory? | Notes |
|---|---|---|
| `POSTGRES_PASSWORD` | yes | Tied to the Postgres data volume. |
| `SESSION_SECRET` | yes | Signs session cookies. 64+ random chars. |
| `OWNCHART_TOKEN_DEK` | yes | Base64 32-byte AES-256 key. Encrypts OAuth tokens at rest. **Losing this means every connected provider must be re-authenticated** — must be backed up. |

Operator-set:

| Variable | Mandatory? | Notes |
|---|---|---|
| `OWNCHART_PUBLIC_BASE_URL` | yes for FHIR | Must match every vendor registration exactly. |
| `ANTHROPIC_API_KEY` | optional | Server-wide default. If unset, users must each configure their own under Settings → LLM Providers (BYO). |
| `OWNCHART_AUTO_EXPORT_TOKEN` | optional | Bearer for Health Auto Export iOS app. When unset the endpoint returns 503. |
| `OWNCHART_EPIC_CLIENT_ID` / `_SANDBOX` | optional | Epic SMART-on-FHIR client ID from `fhir.epic.com`. |
| `OWNCHART_ATHENA_CLIENT_ID`, `OWNCHART_MODMED_CLIENT_ID`, etc. | optional | Per-vendor. See `user-docs/CONNECTORS.md`. |
| `OWNCHART_DEBUG_PAYLOADS` | leave unset in prod | Raw bodies in logs. PHI risk. Dev only. |
| `OWNCHART_DEMO_MODE` | leave unset | `true` only on the public demo. |

## Demo posture (Docs should not overstate)

- Demo runs with `OWNCHART_DEMO_MODE=true`. The read-only
  middleware blocks all mutating writes except for the explicit
  allowlist: auth, consent, conversations, episodes, sensemaking,
  home, ask. So evidence (sources, facts) cannot be added; the
  patient record stays exactly what the seed bundle produced.
- **Demo conversations are written against the shared `demo@ownchart.me`
  account.** A visitor's chat with the LLM is stored on that
  account and visible to the next visitor's conversation list.
  Docs should warn visitors not to type real PHI into the demo
  Ask box. Alpha caveat; a per-session demo identity is
  beta-scope (would change auth surface — out of alpha freeze).
- Demo upload support requires `OWNCHART_DEMO_ALLOW_INGEST=true`
  AND the reverse-proxy body-size widen on the demo host. We are
  NOT changing NPM / Cloudflare on the public demo for alpha.
  Docs should document this as a known alpha limitation: the
  public demo is read-only by design.
